# Emerald bridge: snapshots up, intents down

This is the second pipeline in the repo. The first (`shadow/`) works with any game and
re-renders pixels from VRAM. This one is specific to Pokémon Emerald (US) and works
from the game's *meaning* instead: where the player and NPCs are, which map you're on,
whether a dialogue or a battle is running. The goal is a client, eventually 3D, that
draws its own world and drives the real game underneath it.

## The contract

The GBA is the only source of truth. The client never stores game state, only
presentation state (camera, interpolation, its own UI). If they disagree, the client
snaps to the GBA.

| Direction | What | Shape |
|---|---|---|
| client → GBA | **Intents**: what the player wants | `goto(x, y)`, `face(dir)`, `interact(local_id \| x, y)`, `advance_text()`, `choose(i)`, `press(buttons)` |
| GBA → client | **Snapshot**: what is true now | map, player, 16 NPCs, mode, text, menu, battle cursors, plus each intent's status |

Events (`map_changed`, `text_opened`, `battle_started`, …) aren't sent. They're
derived by comparing consecutive snapshots (`emerald/events.py`), so none can be lost
or arrive out of order.

## The loop

`EmeraldHost.step()` (`emerald/host.py`) runs exactly one GBA frame, synchronously,
inside the client's process:

```
keys = controller.step(last_snapshot, grid) | raw_keys   # intent -> buttons
core.set_keys(keys); core.run_frame()                     # libmgba, in-process
snapshot = read_snapshot(core)                            # via pokeemerald symbols
events = diff(previous, snapshot)
```

The emulator is libmgba behind a small C API (`host/gbahost.c`, loaded with ctypes by
`shadow/core.py`). Memory regions are zero-copy NumPy views of mGBA's buffers. The
loop has no sockets, threads or dropped frames, and both sides always agree on which
frame it is. To hold the game, e.g. while a 3D door animation finishes, the client
simply doesn't call `step()`.

## Modes

Every snapshot has exactly one mode. It decides which intents are accepted, and a
mode change ends any intent that can't continue:

| Mode | When (from memory) | Accepted |
|---|---|---|
| `OVERWORLD` | `gMain.callback2 == CB2_Overworld`, field controls unlocked, on foot or surfing | `goto`, `face`, `interact` |
| `SCRIPT` | field controls locked and a script, message box or yes/no/multichoice menu is active | `advance_text`, `choose` |
| `DIRECT` | on the Mach or Acro bike | raw input only (client mirrors) |
| `SCREEN` | battle, start menu, bag, title, intro… (any other `callback2`) | raw input only; show the GBA screen |
| `TRANSITION` | palette fade, map load, locked with nothing running | nothing; wait |

`press()` and raw input work in every mode. Raw d-pad input in `OVERWORLD` cancels
the running intent (`aborted: user_input`).

## Intents and how they end

Each intent ends `done` or `aborted` with a reason:

- `goto(x, y)` snaps an unreachable target to the nearest reachable tile (`args.snapped_to`)
  unless `exact=True`. It runs if the player has the Running Shoes, replans around NPCs,
  and follows map connections (the goal is shifted by the game's coordinate change).
  Reasons: `arrived`, `warped` (the last step was a door), `script` (trainer or step
  trigger), `screen:BattleMainCB2` (wild encounter), `blocked`, `unreachable`, `replaced`.
- `interact(local_id=…)` / `interact(x=…, y=…)`: walks next to the target, re-picks the
  approach if the NPC wanders, turns, presses A. `done: started:script` once the game
  reacts.
- `advance_text(until_closed=False)` presses A once. With `until_closed=True` it keeps
  going, but stops when a menu appears so it never answers one by accident.
- `choose(i)` moves the yes/no or multichoice cursor and confirms; `choose(-1)` presses B.

## Pathfinding

`emerald/mapgrid.py` reads `gBackupMapLayout` every frame: the current map plus a
7-tile margin that holds the connected maps. Runtime changes (opened doors, cut trees,
`setmetatile`) are therefore always current. Passability follows the game's
`GetCollisionAtCoords` and `CheckForObjectEventCollision`: collision bits, elevation
(including stepping off water while surfing), one-way walls (`MB_IMPASSABLE_*`), ledges
(jump only in their direction, landing two tiles on), and the map edge where there's
no connection. A* searches over (x, y, elevation, direction) and penalises turns a
little, so of the equally short paths it picks the straightest.

## Data

`emerald/data/bpee.json` is generated by `tools/gen_emerald_data.py` from the pret
decomp and the `pokeemerald.sym` that pret publishes on its `symbols` branch. It holds
only addresses, enum values, map and object names, and the text encoding. Struct
offsets used by the reader are written next to each read, with the decomp struct they
come from.

## What has been verified, and what hasn't

Verified here:

- The in-process core reproduces mGBA exactly: shadow renders from host memory match
  mGBA's framebuffer on 122/122 test-ROM frames (`tests/test_core.py`).
- The controller's closed loop (walking, running, ledges, water, NPC replanning,
  turning, dialogue, yes/no, trigger and encounter interrupts, map connections) works
  against `emerald/fake.py`. The fake uses the real symbol addresses and struct
  layouts, and models the game's input rules (turn in place only from a standstill, A
  ignored mid-turn, one new press per release).

**Not yet verified:** nothing has been run against a real Emerald ROM, because I don't
have one. Every struct offset comes from the decomp, but these assumptions need
checking first:

1. `gPaletteFade.active` is bit 7 of byte 7 (follows from GCC bitfield packing).
2. The map-connection goal shift: whether the game changes maps on the frame a step
   starts or the frame it ends.
3. Mode heuristics around warps, the start menu and scripted cutscenes, e.g. whether
   any field effect leaves controls locked with no script running for a long time.
4. `boot` (pressing through the intro) has never been run.

Run `tests/test_emerald_rom.py` with `EMERALD_ROM` (and `EMERALD_STATE`) set, and use
`python -m emerald probe` to compare snapshots with what's on screen.
